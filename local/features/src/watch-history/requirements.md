## 仕様定義書──「watch-history」草稿

> **注**：本書は実装着手前の仕様整理を目的としています。Cursor 等にて開発を進める折の指針とならんことを期しています。

---

### 1. 目的・背景

* ニコニコ動画の非プレミアム会員に課せられし **視聴履歴 50 件制限** を打破し、
  **無制限かつ高機能なローカル履歴** を実現します。
* 視聴行動を詳細に記録・可視化し、再発見と自己分析を助けます。
* いかなる外部課金・クラウド依存も排し、**完全クライアント完結** を旨とします。

### 3. 全体構成

1. **埋込スクリプト**

   * 視聴ページで動画メタデータ＆視聴イベントを取得し `IndexedDB` へ保存します。
2. **履歴ビュー SPA**

   * DB を読込み、GUI を描画して操作を受け付けます。
3. **ローカルプロキシ**

   * HTML へ `<script type="module" src="...">` を噛ませる挿入を担います。

---

### 4. データフロー概要

1. **ページロード時**

   * src/common/common.ts の window.commonHelper.fetchWatchPage を使用して、
   * タイトル・投稿者・動画長など静的項を得ます。
2. **視聴開始**

   * `openentry` を生成し `watchCount++`、`watchedAt = now` で upsert。
3. **進捗記録**

   * `<video>` の `timeupdate` を 15 s デバウンス。
   * `lastPosition` を更新します。
4. **完走判定**

   * `ended` or `(currentTime / duration) ≥ 0.95` で `completed = true` に。
5. **再視聴時**

   * 旧エントリ上書き、履歴内の順序更新。
   * **視聴ログ配列** に追記し視聴回数 & 時系列を保持。
6. **履歴ビュー**

   * `IndexedDB` 全件読込 → ソート・検索 → 画面描画。
   * UI 操作に合わせ都度クエリ or in‑memory filter を行います。

---

### 5. IndexedDB スキーマ

| フィールド                   | 型                | 意味                               |             |
| ----------------------- | ---------------- | -------------------------------- | ----------- |
| `videoId`               | string (KeyPath) | `sm12345` 等                      |             |
| `title`                 | string           | 動画名                              |             |
| `ownerId` / `ownerName` | string           | 投稿者                              |             |
| `lengthSec`             | number           | 再生長（秒）                           |             |
| `watchedAt`             | number           | 最終視聴 Epoch ms                    |             |
| `firstWatchedAt`        | number           | 初回視聴 Epoch ms                    |             |
| `lastPosition`          | number           | 進捗（秒）                            |             |
| `completed`             | boolean          | 95 % 以上なら真                       |             |
| `watchCount`            | number           | 累積視聴数                            |             |
| `watchLogs`             | array            | `{date, position, completed}` 配列 |             |
| `stats`                 | object           | null                             | 再生数・コメント数など |
| `tags`                  | string\[]        | 公式タグ                             |             |
| `thumbnailUrl`          | string           | URL                              |             |
| `memo`                  | string           | 手書きメモ                            |             |

> **Index**：`watchedAt` 降順 / `ownerId` / `completed` を作成します。

### 6. 履歴ビュー UI 要件

#### 6.1 レイアウト

```
 ┌──────────── 左サイドバー ───────────┐ ┌───────── 右：アイテム欄 ────────┐
 │ 検索バー [_______]                    │ │ ┌───サムネ──┐   動画タイトル        │
 │ ───────── ソート項目 ───────── │ │ │   画像   │  投稿者 ／長さ…          │
 │ ▸ 年 Asc/Desc                         │ │ └────────┘  視聴日時   進捗95% │
 │ ▸ 月 …                               │ │  メモ欄 ✎                       │
 │ ▸ 日 …                               │ │ ───────────────────────── │
 │ ▸ 時間帯 …                           │ │ 2件目 …                       │
 │ ▸ 投稿者 …                           │ └───────────────────────────┘
 │ …                                    │
 └───────────────────────────────────┘
```

#### 6.2 機能

* **ソートトグル**：オプションで昇降順切替です。
  * 年別、月別、日別、時間別、投稿者別、タイトル昇順降順、再生数昇順降順、コメント数昇順降順、マイリスト数昇順降順、いいね数昇順降順、再生時間昇順降順、投稿日時昇順降順、視聴日昇順降順、一番目のタグ昇順降順でソート可能。
* **検索バー**：入力即時フィルタ。対象は **全メタデータ**。
* **アイテム詳細**：

  * サムネ・全メタを列挙。
  * 視聴率は整数％表示、95% 以上は 100% と記します。
  * **視聴回数ラベル** を押下でアコーディオン展開 → 過去各回の日時 & 完了率一覧。
* **インポート / エクスポート**：

  * JSON 形式。エクスポート時は `download` 属性付き Blob。
  * インポート時は差分マージ & 最新 `watchedAt` 優先。
* **タブ切替**：

  1. **履歴**（一覧 UI）
  2. **統計**

     * 日別棒グラフ（Canvas）
     * 総視聴時間 & 完走率
     * Peak 時間帯など（任意拡張）

### 7. 動作要件詳細

1. **同動画複数視聴**

   * DB ではエントリ 1 つに更新。`watchLogs` に履歴追記。
   * 一覧は常に最新視聴日時を反映。
2. **メタデータ更新**

   * 再視聴時、視聴ページから再取得し差し替え。統計値の旧値保持は任意。
3. **並び順保持**

   * ソート状態・検索語は `sessionStorage` に覚え、ページ再移動で復元。
4. **容量対策**

   * 初期は無制限。10 000 件超過時に古い `watchLogs` の細粒度削減など警告表示（後日実装可）。
5. **パフォーマンス**

   * 一覧描画 2 000 件以内を目標 50 ms 以内。
   * 仮想スクロール導入は 5 000 件超過後に検討。
6. **アクセシビリティ**

   * キーボード操作のみで主要機能に到達可。
   * ARIA ロール付与。
7. **セキュリティ**

   * 外部送信なし。インポート JSON は構造検証の上マージ。
8. **ブラウザ互換**

   * Firefox ESR + Chrome LTS 現行で確認。
   * Safari は UI 描画崩れなきことを参考実装後に確認。
