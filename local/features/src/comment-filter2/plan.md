# CommentFilter2 実装計画書

## 1. プロジェクト概要
CommentFilter2は、CommentFilterの後継として、動画コメントのフィルタリングを行う軽量かつ堅牢なライブラリを目指すのじゃ。以下のコンセプトを基に設計する：
- **必要十分**: 必要最低限の機能に絞り、複雑さを排除。
- **ミニマム**: シンプルなUIと機能でメンテナンス負担を軽減。
- **メンテナンスフリー（堅牢）**: モジュール分離と再利用性を高め、保守性を向上。

主な機能：
- コメントデータのインターセプトとフィルタリング（Proxy経由）。
- グローバルオブジェクトを介したデータ取得部とフィルター部の分離。
- video_playerライブラリとの連携（`video-element`存在時）。
- シンプルなNGワードルール設定（正規表現、置換表現、動画SMID、ニコる数）。
- インポート/エクスポート機能。
- デバッグモードと全体ON/OFFトグルスイッチ。

## 2. アーキテクチャ設計
### 2.1 全体構造
CommentFilter2は以下の主要モジュールで構成する：
- **データ取得部（Proxy）**: APIエンドポイントをインターセプトし、コメントデータを取得。
- **フィルター部**: グローバルオブジェクト経由で取得したコメントをフィルタリング。
- **UIマネジメント部**: シンプルなUIを提供（NGワード設定、トグルスイッチなど）。
- **IndexedDB部**: NGワードルールや設定をローカルに保存。
- **ユーティリティ**: サニタイズ、定数、スタイル、テンプレートなど。

### 2.2 データフロー
1. Proxyが`https://public.nvcomment.nicovideo.jp/v1/threads`をインターセプトし、JSONデータを取得。
2. 取得データをグローバルオブジェクト（例: `window.CommentFilter2Data`）に格納。
3. フィルター部がグローバルオブジェクトからデータを取得し、NGワードルールに基づきコメントを改変。
4. video_player使用時（`<video id="video-element">`存在時）、video_playerのコメントデータをグローバルオブジェクト経由でフィルター部に渡し、フィルタリング済みコメントを返す。
5. UIマネジメント部でユーザーが設定したルールをIndexedDBに保存し、フィルター部に適用。

### 2.3 モジュール分離の利点
- フィルター部を独立させることで、他のプロジェクトやvideo_playerとの再利用が可能。
- グローバルオブジェクトによる疎結合で、メンテナンス性と拡張性を向上。

## 3. 機能仕様
### 3.1 データ取得部（Proxy）
- **対象エンドポイント**: `https://public.nvcomment.nicovideo.jp/v1/threads`
- **データ構造**:
  ```json
  {
    "meta": { "status": 200 },
    "data": {
      "globalComments": [{ "id": "1635129483", "count": 397 }],
      "threads": [
        { "id": "1635129483", "fork": "owner", "commentCount": 0, "comments": [] },
        {
          "id": "1635129483",
          "fork": "main",
          "commentCount": 255,
          "comments": []
        },
        {
          "id": "1635129483",
          "fork": "easy",
          "commentCount": 139,
          "comments": []
        }
      ]
    }
  }
  ```
  - コメントデータ構造: `id`, `no`, `vposMs`, `body`, `commands`, `userId`, `isPremium`, `score`, `postedAt`, `nicoruCount`, `nicoruId`, `source`, `isMyPost`
  ```json
            {
            "id": "902044328820572160",
            "no": 3,
            "vposMs": 76820,
            "body": "1分20秒ぶりに聞く肉声がこいつなのイヤだ",
            "commands": ["184"],
            "userId": "TKAF1N8IB3c8D0WJ3l8xixNrwyQ",
            "isPremium": true,
            "score": 0,
            "postedAt": "2021-10-25T13:02:07+09:00",
            "nicoruCount": 22,
            "nicoruId": null,
            "source": "trunk",
            "isMyPost": false
            },
  ```
  - コメントコマンド:【大きさ】:big,medium,small【フォント】:defont,gothic,mincho【位置】:ue,naka,shita, デフォルト(指定なし)の場合、medium,defont,nakaになる。【半透明】:_live【非表示】:invisible,【横幅の長い固定コメントの縮小幅を、16:9画面の幅に合わせる。4:3動画でも適用可。】:full,【改行によるリサイズを適用しない】:ender,【このコマンドをつけたコメントが表示されなくなるタイミングを従来の方式に変更する 】:patissier,【ニコられてもコメントが消えにくくならないようにする。】:ca,一般+プレミアム:white, red, pink, orange, yellow, green, cyan, blue, purple, black,プレミアムオンリー:white2, red2, pink2, orange2, yellow2, green2, cyan2, blue2, purple2, black2,#16進数(HEX)で指定する色
  - 公式動画では`fork: "main"`が複数ある場合、`commentCount`が最多のスレッドを選択。
- Proxyは取得データをグローバルオブジェクトに保存し、フィルター部に通知。

### 3.2 フィルター部
- **NGワードルール**:
  - 形式: `/正規表現/,/置換後表現/,(動画SMID),ニコる数`
    - `/正規表現/`: NGワードを正規表現で指定。gオプションとiオプションに対応。（対応する方法は考える）
    - `/置換後表現/`: `/EMPTY/`なら非表示、それ以外は置換。
    - `(動画SMID)`: `ALL`なら全動画、特定のSMIDならその動画のみ対象。
    - `ニコる数`: 指定数以上のニコられでフィルター無視（例: `3`なら3ニコられ以上で適用除外）。未指定は`EMPTY`。
  - 例: `/fuck/,/****/,ALL,3` → 全動画で`fuck`を`****`に置換、ニコられ3以上は無視。
- **コメント種別対応**:
  - 簡単コメント（`fork: "easy"`）、メインコメント（`fork: "main"`）、投稿者コメント（`fork: "owner"`）にコマンド適用。
  - 確実な適用のため、コメントに`isPremium: true`を設定。
- フィルタリング済みデータをグローバルオブジェクトに保存し、video_playerやUIに返す。

### 3.3 UIマネジメント部
- **UI構成**:
  - NGワード入力用テキストボックス（形式: `/正規表現/,/置換後表現/,(動画SMID),ニコる数`）。
  - インポート/エクスポートボタン。
  - デバッグモードトグル（フィルタリング状況表示）。
  - 全体ON/OFFトグルスイッチ。
- シンプルで直感的なデザインを採用し、CommentFilterの複雑なUIを排除。

### 3.4 IndexedDB部
- NGワードルールや設定をローカルに保存。
- スキーマ:
  ```json
  {
    "rules": [
      { "regex": "/fuck/", "replace": "/****/", "smid": "ALL", "nicoru": 3 },
      ...
    ],
    "settings": { "debugMode": false, "isEnabled": true }
  }
  ```
- インポート/エクスポート機能でJSON形式のルールデータを入出力。

### 3.5 その他ユーティリティ
- **定数ファイル**: APIエンドポイント、グローバルオブジェクト名など。
- **サニタイズユーティリティ**: ユーザー入力の正規表現やコメントデータの安全性を確保。
- **スタイルファイル**: ミニマムなCSS（例: Tailwind CSS）。マテリアルアイコンは`material-icons.ts`経由で提供されるnpm版を使用する。
- **テンプレートファイル**: UIのHTMLテンプレート。

## 4. 実装計画
### 4.1 ステップ・バイ・ステップ
1. **データ取得部の実装**:
   - Proxyをセットアップし、指定エンドポイントをインターセプト。
   - 公式動画の`main`スレッド選択ロジックを実装。
   - グローバルオブジェクトにデータを保存。
2. **フィルター部の実装**:
   - NGワードルールの解析と適用ロジックを構築。
   - ニコる数やSMIDに基づく条件分岐を実装。
   - コメントに`isPremium: true`を適用。
3. **UIマネジメント部の実装**:
   - テキストボックス、トグルスイッチ、インポート/エクスポートボタンをReact+Tailwindで構築。
   - デバッグモードでフィルタリング結果を視覚化。
4. **IndexedDB部の実装**:
   - ルールと設定の保存/取得機能。
   - JSON形式でのインポート/エクスポート機能。
5. **video_player連携**:
   - `video-element`存在時にvideo_playerのコメントデータをグローバルオブジェクト経由で処理。
6. **ユーティリティ実装**:
   - サニタイズ、定数、スタイル、テンプレートを整備。

### 4.2 開発スケジュール（仮）
- 週1: データ取得部、フィルター部のプロトタイプ完成。
- 週2: UIマネジメント部、IndexedDB部の実装。
- 週3: video_player連携とユーティリティの実装。
- 週4: テスト、デバッグ、ドキュメント整備。

## 5. 考慮事項
- **エラー処理**: APIエラーや無効な正規表現への対応。
- **パフォーマンス**: 大量コメントのフィルタリング最適化（例: 正規表現キャッシュ）。
- **セキュリティ**: ユーザー入力のサニタイズを徹底。
- **互換性**: video_playerや各種ブラウザでの動作確認。

## 6. 期待される成果
- シンプルで堅牢なコメントフィルタリングシステム。
- 再利用可能なフィルター部による拡張性の向上。
- メンテナンス負担の軽減とユーザー体験の向上。
